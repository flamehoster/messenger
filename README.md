# MAX (Drognev): защищённый мессенджер

Веб-мессенджер со сквозным шифрованием. Сообщения шифруются на устройстве отправителя и расшифровываются только у получателя. Сервер пересылает непрозрачные зашифрованные конверты. Он не может прочитать ни текст, ни файлы и не знает, кто отправил сообщение.

- Регистрация без телефона и почты: только имя пользователя и ключи, созданные на устройстве.
- Протокол **X3DH + Double Ratchet**, как в Signal: у каждого сообщения свой ключ.
- **Запечатанный отправитель**: сервер видит получателя, но не отправителя.
- **Код безопасности** из 60 цифр для проверки, что никто не подменил ключи. При смене ключа собеседника отправка блокируется до повторной проверки.
- Исчезающие сообщения: таймер от 30 секунд до недели, синхронизируется у обоих собеседников.
- Можно очистить историю чата сразу у обоих.
- Файлы и картинки до 3 МБ, тоже со сквозным шифрованием.
- Локальное хранилище зашифровано паролем. Есть автоблокировка, размытие экрана в неактивном окне и опциональное самоуничтожение после N неверных паролей.
- Отчёты о доставке (✓✓) можно отключить.

## Быстрый старт (локально)

```bash
npm install
npm start
```

Откройте http://localhost:8080. Для проверки переписки откройте второй профиль браузера или окно инкогнито и зарегистрируйте второго пользователя.

> Браузер даёт доступ к криптографии только на `localhost` или по **HTTPS**. Нужен актуальный Chrome, Edge, Firefox или Safari с поддержкой X25519/Ed25519 в WebCrypto.

## Запуск в PyCharm

1. Установите **Node.js 22 LTS** или новее с https://nodejs.org (сам мессенджер написан на Node.js). После установки перезапустите PyCharm.
2. В PyCharm выберите **File → Open** и откройте папку `messenger`. Если PyCharm спросит, доверять ли проекту, нажмите **Trust Project**.
3. Вверху справа выберите конфигурацию **MAX server** и нажмите ▶. Можно и так: правый клик по `run.py` → **Run 'run'**.
4. При первом запуске `run.py` сам установит зависимости, затем запустит сервер и откроет браузер на http://localhost:8080.

Если PyCharm пишет, что интерпретатор не настроен, выберите любой Python 3.8+ в **Settings → Project → Python Interpreter**. Сторонние Python-пакеты не нужны.

Для проверки переписки откройте второй профиль браузера или окно инкогнито и зарегистрируйте второго пользователя.

## Запуск на сервере

Нужен VPS с Docker и доменом, у которого A-запись указывает на сервер.

1. Впишите свой домен в `Caddyfile`.
2. Запустите:
   ```bash
   docker compose up -d
   ```

Caddy сам получит сертификат Let's Encrypt. Журналы Docker и Caddy отключены. Контейнер мессенджера работает без root, с файловой системой только для чтения и без Linux capabilities.

Переменные окружения сервера:

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT`, `HOST` | `8080`, `127.0.0.1` | где слушать |
| `DATA_DIR` | `./data` | хранилище открытых ключей и очередей |
| `TLS_CERT`, `TLS_KEY` | — | пути к сертификату, если HTTPS без прокси |
| `TRUST_PROXY` | `0` | `1` — брать IP из `X-Forwarded-For` (только за своим прокси) |
| `HSTS` | `0` | `1` — отдавать `Strict-Transport-Security` |
| `ALLOWED_ORIGINS` | тот же хост | список разрешённых Origin через запятую |
| `REGISTER_PER_HOUR` | `5` | лимит регистраций с одного IP в час |

## Запуск на Render.com

1. Войдите на https://render.com через GitHub.
2. Нажмите **New → Blueprint** и выберите репозиторий `messenger`. Render прочитает `render.yaml` и создаст сервис с диском на 1 ГБ.
3. Нажмите **Apply** и дождитесь сборки (2–3 минуты).
4. Откройте адрес вида `https://max-drognev-xxxx.onrender.com`. HTTPS Render включает сам.

Нужен тариф **Starter** (около $7 в месяц), потому что аккаунты хранятся на диске `/var/data`. На бесплатном тарифе диска нет: при каждом перезапуске или засыпании сервиса (после 15 минут без запросов) все аккаунты и недоставленные сообщения стираются. Для пробы это подойдёт, для постоянного общения — нет.

Чтобы попробовать бесплатно: **New → Web Service**, репозиторий `messenger`, Build Command `npm ci --omit=dev`, Start Command `node server/server.js`, Instance Type **Free**. Больше ничего настраивать не нужно: сервер сам определяет, что работает на Render.

## Как устроена защита

### Криптография

Используется только стандартный WebCrypto, без сторонних криптобиблиотек.

| Что | Чем |
|---|---|
| Ключ личности | Ed25519 (подпись) + X25519 (DH), DH-ключ подписан Ed25519 |
| Установление сессии | X3DH: ключ личности, подписанный предключ (ротация раз в 7 дней), одноразовые предключи (сервер выдаёт каждый ровно один раз) |
| Сессия | Double Ratchet: HKDF-SHA256 для корневой цепочки, HMAC-SHA256 для цепочек сообщений |
| Шифрование сообщения | AES-256-GCM; заголовок храповика и ключи обеих сторон входят в associated data |
| Конверт для сервера | эфемерный X25519 → HKDF → AES-256-GCM на ключ получателя (запечатанный отправитель) |
| Выравнивание длины | ISO/IEC 7816-4: блоки 256 Б, для крупных сообщений 16 КБ |
| Код безопасности | 5200 итераций SHA-512, 60 цифр |
| Локальное хранилище | PBKDF2-SHA256, 600 000 итераций → AES-256-GCM, неизвлекаемый ключ в IndexedDB |

Что это даёт:
- **Прямая секретность.** Если ключи украдут сегодня, вчерашние сообщения всё равно не расшифровать.
- **Самовосстановление.** После компрометации защита возвращается после следующего обмена репликами.
- **Устойчивость к подделке и повтору.** Изменённое или повторно присланное сообщение отвергается, и состояние сессии от этого не портится.
- **Защита от подмены отправителя.** Если новый ключ приходит под чужим именем, клиент сверяет его с сервером. При расхождении сообщение отбрасывается.

### Сервер

- Хранит только открытые ключи и зашифрованные конверты, пока они не доставлены (не дольше 30 дней).
- Не записывает отправителя, IP-адреса, журналы и список контактов. Время сообщения округляется до минуты.
- Вход по подписи случайного вызова ключом Ed25519. Паролей на сервере нет.
- Сжатие WebSocket отключено, чтобы не раскрывать длину содержимого (атаки класса CRIME).
- Лимиты частоты запросов, проверка Origin, ограничение размеров.
- HTTP-заголовки: строгая CSP (`default-src 'none'`, только свои скрипты), **Trusted Types** (запрет `innerHTML` на уровне браузера), COOP/COEP/CORP, `frame-ancestors 'none'`, `Referrer-Policy: no-referrer`, запрет камеры, микрофона и геолокации, `Cache-Control: no-store`.

### Клиент

- Интерфейс строится только через `textContent`, поэтому HTML в сообщениях отображается как текст.
- Вложения, кроме PNG, JPEG, GIF и WebP, отдаются как `application/octet-stream`: присланный HTML или SVG не запустится в контексте мессенджера.
- Проверка орфографии в поле ввода выключена: некоторые браузеры отправляют текст в облако для проверки.
- Открыть мессенджер можно только в одной вкладке, чтобы две копии не повредили ключи.
- Блокировка перезагружает страницу, и ключи гарантированно стираются из памяти. Горячая клавиша: Ctrl+Shift+L.

## Ограничения

Абсолютной защиты не бывает. Важно понимать, от чего этот мессенджер **не** защищает:

1. **Сервер раздаёт код клиента.** Взломанный или недобросовестный сервер может подсунуть изменённый JavaScript. Это общая проблема веб-мессенджеров. Защищайтесь так: держите сервер сами и проверяйте код.
2. **Метаданные.** Сервер видит, кому пришло сообщение, его примерный размер и время с точностью до минуты, а в момент соединения — IP-адрес. IP не сохраняется, но хостинг его видит. Для анонимности подключайтесь через Tor или VPN.
3. **Устройство.** Вирус, кейлоггер или чужой человек за разблокированным экраном обходят любое шифрование.
4. **Нет независимого аудита.** Протокол повторяет схему Signal и покрыт тестами, но реализация собственная и внешнего аудита не проходила.
5. **Одно устройство на аккаунт.** При входе с нового устройства старая сессия завершается, а при потере пароля переписку не восстановить.
6. **PBKDF2, а не Argon2.** В WebCrypto нет Argon2, поэтому стойкость хранилища сильно зависит от длины пароля. Используйте фразу из 4–5 случайных слов.

## Тесты

```bash
npm test                         # протокол + сквозной тест с настоящим сервером (Node)
node test/browser-smoke.mjs      # сценарий в Chromium (нужен playwright)
```

Тесты проверяют X3DH и Double Ratchet, сообщения вне очереди, отказ при повторе и подделке, одноразовость предключей, запечатанный конверт, совпадение кодов безопасности, офлайн-доставку, смену ключа собеседника, попытку подмены отправителя, отсутствие открытого текста на сервере, XSS в сообщении и блокировку второй вкладки.

## Структура

```
server/server.js     HTTP + WebSocket, заголовки безопасности, лимиты
server/store.js      открытые ключи и очереди конвертов (JSON, права 600)
public/js/crypto.js  примитивы WebCrypto
public/js/protocol.js X3DH, Double Ratchet, запечатанный конверт, код безопасности
public/js/core.js    логика клиента без интерфейса
public/js/vault.js   зашифрованное локальное хранилище
public/js/net.js     транспорт
public/js/app.js     интерфейс
```
